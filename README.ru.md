# Collection Viewer

Плагин для Dalamud (Dalamud v15, Final Fantasy XIV), который показывает коллекцию персонажа с
сайта [FFXIV Collect](https://ffxivcollect.com) — маунты, минионы, оркестрионы, эмоции, причёски
и бардинги — прямо в игре.

> **Сделано с помощью ИИ.** Код, архитектура и документация этого плагина созданы ИИ-ассистентом
> для программирования (Claude Code / Anthropic Claude) на основе требований и итеративной
> обратной связи от автора. Прежде чем полагаться на плагин, стоит проверить его самостоятельно.

🌐 English version: [README.md](README.md)

## Языки интерфейса

**English** (по умолчанию) и **Русский** — переключаются в любой момент в настройках
(`/pcollection config` → Language). Все окна, фильтры, сообщения об ошибках и пункт контекстного
меню обновляются сразу же при переключении.

## Возможности

- **Моя коллекция** — команда `/pcollection` открывает коллекцию персонажа с ID, сохранённым в
  настройках. Кнопка «Определить автоматически» в настройках находит его по текущему
  залогиненному персонажу.
- **Просмотр коллекции любого игрока** — ПКМ по игроку везде, где игра показывает стандартное
  контекстное меню (чат, список party/alliance, таргет оф таргет и т.д.) → «Посмотреть коллекцию
  (FFXIV Collect)».
- **Шесть категорий коллекции**: маунты, минионы, оркестрионы, эмоции, причёски, бардинги. По
  каждой — прогресс (получено/всего) с процентной шкалой.
- **Список предметов** по категории с иконками; для недостающих предметов — минимальная текущая
  цена на маркете, известная FFXIV Collect (в гилах).
- **Фильтры**, комбинируются между собой: полученные / недостающие / все, продаются на маркете /
  не продаются / все, диапазон цены в гилах (от / до) для продаваемых предметов.
- **Сортировка**: по названию, сначала дешёвые, сначала дорогие. Полученные предметы всегда идут
  отдельной группой перед недостающими; сортировка применяется внутри каждой группы.
- **Поиск** по названию предмета внутри категории.
- **Кэширование** — ответы кэшируются в памяти и на диске с настраиваемым временем жизни
  (по умолчанию 30 минут), поэтому повторное открытие коллекции не дёргает API заново, пока кэш
  свежий. Кнопка «Обновить» форсирует повторный запрос.
- Футер каждого окна ссылается на ffxivcollect.com (некоммерческий личный проект, не аффилирован
  с FFXIV Collect).

## Как это устроено

```
CollectionViewer/
  Api/            HTTP-клиент FFXIV Collect (FfxivCollectClient) и DTO-модели ответов
  Data/           Статические справочники: категории коллекции, таблица мир → регион Lodestone
  Services/
    LodestoneResolver    находит Lodestone ID по имени персонажа и миру (подробнее ниже)
    CollectionService    кэш в памяти + на диске с TTL, находится между UI и API-клиентом
    IconTextureCache     загружает иконки предметов и превращает их в ImGui-текстуры
    ContextMenuService   добавляет пункт ПКМ-меню «Посмотреть коллекцию»
  Windows/
    CollectionWindow     единое переиспользуемое окно-просмотрщик (своя коллекция или любой
                          найденный персонаж)
    ConfigWindow          настройки: язык, свой ID персонажа, TTL кэша
  Utility/          AsyncOperation<T> (связывает асинхронные запросы с синхронным циклом
                    отрисовки ImGui), форматирование сообщений об ошибках
  Configuration.cs   IPluginConfiguration (язык, свой ID, TTL кэша)
  Localization.cs    все строки интерфейса для обоих языков
  Plugin.cs           точка входа: связывает сервисы, регистрирует команду, контекстное меню
                      и элемент в Server Info Bar
```

### Как устроен поиск персонажа

FFXIV Collect использует **Lodestone ID персонажа** как свой собственный ID — это подтверждено
напрямую: `ffxivcollect.com/api/characters/1` — это тот же самый персонаж, что и
`lodestone/character/1/`. Отдельного «номера аккаунта FFXIV Collect» не существует.

У публичного API FFXIV Collect нет эндпоинта для поиска персонажа по имени или миру, и нет
эндпоинта для проверки произвольного Lodestone ID через поиск. Единственный способ превратить
«имя игрока и его домашний мир» в Lodestone ID — это сама страница поиска Lodestone, у которой нет
JSON API, только HTML. Поэтому поиск игрока, выбранного через ПКМ (или своего персонажа через
«Определить автоматически»), — это best-effort скрейпинг HTML этой страницы поиска
(`Services/LodestoneResolver.cs`) с сопоставлением по точному имени и миру. Если найденный ID не
зарегистрирован на FFXIV Collect (или профиль/коллекция скрыты), об этом сообщается прямо в окне
понятным текстом, а не тихим сбоем.

Поскольку это зависит от разметки страницы Lodestone, поиск по имени в принципе best-effort —
изменение вёрстки Lodestone может потребовать правки регулярного выражения в коде. Надёжный
способ — один раз ввести свой FFXIV Collect / Lodestone ID в настройках (это просто число из
адреса вашего профиля).

## Сборка

Требуется:
- .NET SDK (собрано и проверено на .NET 10 SDK; проект таргетирует то, что резолвит
  `Dalamud.NET.Sdk/15.0.0`)
- Локально установленный Dalamud/XIVLauncher, чтобы SDK нашёл dev-хуки
  (`%AppData%\XIVLauncher\addon\Hooks\dev\`) — для CI это не требуется, см. workflow релиза.

```
dotnet build CollectionViewer.sln -c Release
```

`Dalamud.NET.Sdk` сам упаковывает собранную DLL и манифест в
`CollectionViewer/bin/x64/Release/CollectionViewer/latest.zip` — отдельный шаг упаковки не нужен.

## Установка

### Через собственный репозиторий (рекомендуется для постоянного использования)

1. В игре: `/xlsettings` → Experimental → Custom Plugin Repositories.
2. Добавить: `https://raw.githubusercontent.com/goodmasta/CollectionViewer/main/pluginmaster.json`
3. Сохранить, затем найти «Collection Viewer» в `/xlplugins` и установить как обычный плагин.

`.github/workflows/release.yml` пересобирает и переиздаёт плагин автоматически при каждом push в
`main`: подставляет версию/время из `<Version>` в csproj в `pluginmaster.json`, переносит
плавающий тег `latest` и обновляет одноимённый GitHub Release вместе со свежесобранным zip.
Для нового релиза достаточно поднять `<Version>` в
`CollectionViewer/CollectionViewer.csproj` и запушить в `main`.

### Как dev-плагин (для локальной разработки)

1. В игре: `/xlsettings` → Experimental → Dev Plugin Locations → добавить путь к
   `CollectionViewer/bin/x64/Debug` (или `Release`).
2. `/xlplugins` → Dev Tools → Installed Dev Plugins → включить Collection Viewer.

## Настройки

`/pcollection config` открывает окно настроек:

- **Language** — English или Русский.
- **Мой персонаж** — свой FFXIV Collect / Lodestone ID, вручную или через «Определить
  автоматически» (по имени и домашнему миру текущего залогиненного персонажа).
- **Кэш** — время жизни кэшированных данных коллекции в минутах.

## Известные ограничения

- Поиск по имени и миру (ПКМ, автоопределение) зависит от разметки страницы поиска Lodestone —
  неофициальный способ, который может сломаться при изменении сайта.
- Иконки запрашиваются в формате PNG (не WebP) через прокси `v2.xivapi.com`, чтобы не зависеть от
  наличия WebP-кодека в системе.
- Таблица мир → регион для Европы/Японии в `Data/WorldRegions.cs` — статический список по
  актуальным датацентрам (Chaos/Light = EU, Elemental/Gaia/Mana/Meteor = JP); всё остальное,
  включая Oceania/Materia (подтверждено прямым запросом), идёт через `na.finalfantasyxiv.com`.
